## 4. 🟠 Vấn đề 4 — Cấu hình `vmarket_network` là no-op

- Commit message nói *"add docker network"* nhưng `vmarket_network` chỉ khai báo
  top-level, **không service nào gắn vào** → `docker compose config` resolve ra
  chỉ còn `default:`, khai báo bị compose bỏ hẳn. Cấu hình chết, không tác dụng.
- **Kiểm chứng trước khi sửa:** `docker inspect` các container đang chạy đều gắn
  vào `vmarket_default` (network default tự tạo theo project name).
- **Xử lý (phương án A — đã thực hiện):** xóa block
  `networks: vmarket_network: driver: bridge`.
  - Lý do: mọi giao tiếp nội bộ (gateway → auth-service/postgres/rabbitmq) chạy
    tốt trên default network qua **DNS nội bộ của Docker** (tên service = hostname).
    DNS hoạt động giống hệt ở cả default lẫn network có tên; khác biệt duy nhất
    của network có tên là **phân đoạn (segmentation)** — thứ chưa cần ở dev local.
  - Phương án B (gắn network thật cho 8 service) bị loại: thêm ~10-12 dòng cấu
    hình, rủi ro quên gắn service (`unknown host` lúc runtime), phải recreate
    container — không mang lại giá trị hiện tại (over-engineering).
- **Kiểm chứng sau sửa:** `docker compose config` không còn tham chiếu
  `vmarket_network`; 7/7 container Up nguyên trạng (không recreate);
  `GET :8080/api/auth/health` → 200.

### 4.1. Phương án tương lai: khi nào và cách dùng network thật

Trigger: prod / security-hardening / tách lộ diện tấn công. Cấu hình mẫu:

```yaml
networks:
  frontend-net:    # chỉ FE + Gateway
  backend-net:     # Gateway + các business service + hạ tầng DB

services:
  frontend:
    networks: [frontend-net]
  api-gateway:
    networks: [frontend-net, backend-net]   # điểm nối duy nhất giữa 2 vùng
  auth-service:
    networks: [backend-net]
  # ... các service khác: [backend-net]
  postgres: / mongo: / redis: / rabbitmq:
    networks: [backend-net]
```

Nguyên tắc & lưu ý khi triển khai:
1. **Gateway là điểm nối duy nhất** giữa `frontend-net` và `backend-net` — FE bị
   compromise không nhìn thấy DB trực tiếp.
2. Sau khi gắn network có tên, **default network sẽ không còn tự gắn** — service
   khai thiếu network sẽ không resolve được tên service khác → luôn chạy
   `docker compose config` + smoke test sau khi sửa.
3. Chuyển network buộc **recreate toàn bộ container** (`docker compose up -d`) —
   lên kế hoạch downtime ngắn khi làm.
4. Cần **chia sẻ hạ tầng giữa 2 compose project** (VD stack test dùng lại DB của
   stack chính): khai network tên cố định (`name: vmarket_backend_net`) và project
   kia gắn bằng `external: true`.
5. DNS nội bộ, healthcheck, `depends_on`, `host.docker.internal` (service chạy
   local qua mvnw) **không thay đổi** — chỉ topology kết nối là khác.

## 5. Sửa lỗi phát sinh khi kiểm chứng deliverable (FE → Gateway → BE)

Các lỗi bắt buộc phải sửa để deliverable chạy được end-to-end:

| Lỗi | Nguyên nhân | Fix |
|---|---|---|
| FE không kết nối được 8080 (ban đầu) | Compose chưa từng `up`, không gì chạy | `docker compose up -d --build` |
| Preflight CORS bị chặn | Gateway WebMVC 5.0.3 **không hỗ trợ** property `globalcors` (chỉ WebFlux có) — cấu hình YAML bị bỏ qua âm thầm | Tạo `api-gateway/.../config/CorsConfig.java`; gỡ block `globalcors` chết khỏi `application.yml` |

Bổ sung `CORSMiddleware` cho 3 service Python (ai-search, recommendation, chatbot) vốn chưa có |
| Service local kết nối nhầm DB local của Windows (PostgreSQL 18 / mongod local chiếm 5432/27017) | Trùng port | Tách `POSTGRES_HOST_PORT=5433`, `MONGO_HOST_PORT=27018` (publish ra host); port nội bộ container giữ 5432/27017; `scripts/vmarket.ps1` tự set `DB_PORT=5433`, `MONGO_PORT=27018` |
| Auth-service chạy lắt nhắt bằng mvnw | Chưa container hóa | Thêm block `auth-service` vào compose (healthcheck, depends_on healthy, env anchor chung); Gateway override `AUTH_SERVICE_URL: http://auth-service:8081`; thêm `AUTH_SERVICE_PORT` vào `.env`/`.env.example` |
