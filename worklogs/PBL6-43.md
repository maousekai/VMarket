## 1. Quyết định thiết kế (đã xác nhận)

| # | Quyết định |
|---|---|
| Khoá tài khoản | Sai mật khẩu **5 lần liên tiếp** → khoá **15 phút**. Đăng nhập đúng reset bộ đếm. Khi khoá thì reset bộ đếm về 0, `locked_until` là cổng chặn |
| User PENDING | **Đăng nhập được**, response `status = PENDING` + claim `email_verified=false` trong JWT. FE hiển thị màn hình "chưa xác thực email", không cho dùng hệ thống bình thường. BE chưa chặn (siết quyền là PBL6-46) |
| Định danh login | **Chỉ email** |
| Refresh token | **Xoay vòng + phát hiện dùng lại**. TTL **15 ngày**. Dùng lại token đã `revoked_at` → thu hồi toàn bộ phiên user |
| Access token | JWT HS256, TTL 15 phút (SRS NFR-SEC-02 ≤ 30'). Claims: `sub`, `email`, `username`, `roles`, `email_verified`, `iss=auth-service` |
| Refresh token dạng | Chuỗi ngẫu nhiên 256-bit base64url (không phải JWT). DB chỉ lưu SHA-256 hex |
| Không enumeration ở login | Email lạ và sai mật khẩu đều trả `401 INVALID_CREDENTIALS` |

## 4. Rà soát code — 9 điểm, xử lý hết

| # | Điểm | Xử lý |
|---|---|---|
| 1 🔴 | `login()` ghi bộ đếm sai rồi `throw ApiException` (RuntimeException) trong cùng `@Transactional` → Spring rollback → **khoá tài khoản không bao giờ có tác dụng ở prod** | `@Transactional(noRollbackFor = ApiException.class)` |
| 2 🔴 | `refresh()` gọi `revokeAllActiveByUserId()` rồi throw `REFRESH_TOKEN_REUSED` → rollback → **thu hồi phiên khi phát hiện đánh cắp là no-op ở prod** | như trên |
| 3 🟠 | `refresh()` không kiểm tra `locked_until` → user bị khoá vẫn lấy được access token mới | Thêm check `isLocked` trong `refresh()`; khi khoá thì thu hồi luôn toàn bộ refresh token (SRS FR-AUTH-06) |
| 4 🟠 | Retry mạng của `/refresh` (token đã xoay vòng) → `REFRESH_TOKEN_REUSED` → đăng xuất user trên mọi thiết bị | Khoảng ân hạn 30s: dùng lại token vừa xoay vòng → chỉ trả `401 INVALID_REFRESH_TOKEN`, không thu hồi chuỗi. Quá 30s mới coi là đánh cắp |
| 5 🟠 | Enumeration/timing: email lạ bỏ qua BCrypt (~1ms), email thật chạy BCrypt (~100ms) | Chạy BCrypt giả (`DUMMY_HASH`) cho nhánh email lạ. (423 khi bị khoá vẫn giữ — cần cho UX, giống quyết định enumeration ở đăng ký) |
| 6 🟠 | Test `@Transactional` che lỗi #1/#2 (rollback không thực sự xảy ra trong test) | `LoginApiTest` / `RefreshApiTest` bỏ `@Transactional`, dọn `@AfterEach`; assert trạng thái DB sau khi throw |
| 7 🟠 | `registerFailedAttempt` read-modify-write `failed_login_attempts`, không nguyên tử → 5 request song song mất tăng, né được khoá | UPDATE nguyên tử `set failed_login_attempts = failed_login_attempts + 1` trong repo |
| 8 🟡 | `RefreshToken.isActive()` là dead code | Bỏ |
| 9 🟡 | `secret` chỉ `@NotBlank`, javadoc nói ≥32 byte nhưng không ép → lỗi `WeakKeyException` khó hiểu ở prod | Thêm `@Size(min = 32)` với message chỉ đúng tên biến |
