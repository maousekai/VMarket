**Sai lệch nhỏ so với đề xuất ban đầu:** cột định danh dùng `VARCHAR(26)` thay vì
`CHAR(26)`. Lý do: khớp mapping mặc định của Hibernate cho `String` (JDBC VARCHAR)
→ tránh lỗi `ddl-auto: validate` do lệch type-code char/varchar, và tránh ngữ nghĩa
đệm khoảng trắng của `bpchar` PostgreSQL. Về mặt lưu trữ ULID 26 ký tự cố định thì
tương đương.

## 4c. Chạy PostgreSQL thật (error-PBL6-41.md) + sửa 2 lỗi

Buổi chạy thử với PostgreSQL thật (Docker + container `vmarket-postgres` cổng 5433)
phát hiện 2 lỗi — đã sửa:

| # | Lỗi | Root cause | Cách sửa |
|---|---|---|---|
| **E-1** 🔴 | Flyway **không bao giờ chạy** trên Spring Boot 4 → schema trống → Hibernate `validate` sập (`missing table [refresh_tokens]`), app không boot được với PostgreSQL | Boot 4 tách `FlywayAutoConfiguration` sang module `spring-boot-flyway`; PR dùng `flyway-core` trần kiểu Boot 2/3 nên auto-config không có trên classpath. Đã xác minh: `spring-boot-autoconfigure-4.1.1.jar` = 0 class Flyway | `pom.xml`: thay `flyway-core` → **`spring-boot-starter-flyway`** (version do BOM 4.1.1 quản), giữ `flyway-database-postgresql` |
| **E-2** 🟠 | `mvnw spring-boot:run` local nối `localhost:5432` (refused) — compose publish cổng **5433** | `application.yml` default `DB_PORT:5432` không khớp `POSTGRES_HOST_PORT=5433`; `.env.example` dùng tên `POSTGRES_*` còn Spring đọc `DB_*` | `application-dev.yml`: override `spring.datasource.url` default `DB_PORT:5433` (container vẫn nhận `DB_PORT=5432` từ anchor). README mục "Chạy local" ghi rõ cổng 5433 + cách override |

E-3 (thông báo `missing table [refresh_tokens]` gây hiểu lầm — thực ra cả 4 bảng
đều thiếu): chỉ là hành vi của Hibernate `SchemaValidator` (dừng ở bảng đầu theo
thứ tự chữ cái), không cần sửa code.

**Kiểm chứng sau sửa** (theo error-PBL6-41.md §6.2): `DB_PORT=5433 mvnw spring-boot:run`
→ log `Migrating schema "public" to version "1 - init auth schema"` → `Successfully
applied 1 migration` → app UP cổng 8081 → `/actuator/health` = `{"status":"UP"}`.
