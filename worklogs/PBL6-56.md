# Worklog — PBL6-56: Gateway rate limit dùng chung một bucket sau nginx và đếm theo từng instance

- **Loại:** Bug
- **Branch:** `fix/PBL6-56-gateway-rate-limit-client-ip`
- **Ngày:** 20/11/2026

---

## 1. Lỗi

- `RateLimitFilter` lấy khoá đếm bằng `getRemoteAddr()`. Trình duyệt đi qua nginx của container
  `frontend`, nên mọi người dùng web có chung một khoá (IP của nginx) và chung hạn mức 200 request/60s.
  Một người gửi dồn là tất cả nhận 429; giới hạn đăng nhập theo IP mất tác dụng.
- `InMemoryRateLimiter` giữ bộ đếm trong RAM, nên mỗi instance gateway đếm riêng.
- Javadoc `RateLimitProperties` ghi "ưu tiên X-Forwarded-For" nhưng code không đọc header này.

## 2. Cách sửa

| Phần | Nội dung |
|---|---|
| `ClientIpResolver` | Chỉ đọc `X-Forwarded-For` khi `remoteAddr` thuộc `app.rate-limit.trusted-proxies` (IP, CIDR hoặc tên host). Duyệt XFF từ phải sang trái, bỏ qua hop đáng tin, lấy hop đầu tiên không đáng tin. Chỉ parse IP literal (không tra DNS cho giá trị client gửi), chuẩn hoá IPv6. Tên host được tra DNS lại mỗi 30s ở luồng nền; tra lỗi thì giữ kết quả cũ tối đa 3 chu kỳ rồi bỏ |
| `bucketKey` | IPv6 gộp theo dải /64 để không xoay địa chỉ trong /64 mà né giới hạn |
| `RedisRateLimiter` | Fixed-window dùng chung qua Redis: Lua script `INCR` + `EXPIRE` (atomic), key `vmarket:gateway:rate-limit:{windowId}:{ip}`, TTL = cửa sổ + 1s |
| Redis lỗi | Ghi cảnh báo, tạm đếm trong RAM của instance (vẫn còn giới hạn), bỏ qua Redis 5s rồi thử lại |
| Cấu hình | `app.rate-limit.store` (`memory` mặc định, `redis` trong docker-compose), `app.rate-limit.trusted-proxies` (rỗng mặc định, `frontend` trong docker-compose). Timeout Redis 200ms, tắt Redis health indicator để Redis không làm gateway DOWN |

Gọi thẳng cổng 8080 của gateway (không qua nginx) vẫn đếm theo IP kết nối; XFF tự gửi bị bỏ qua.

## 4. Việc còn lại (ngoài phạm vi ticket)

- Redis không có mật khẩu và mở cổng 6379 ra host. Giờ Redis giữ bộ đếm chống brute-force, ai vào được
  cổng này có thể xoá bộ đếm. Nên đặt `requirepass` và chỉ bind `127.0.0.1` (ảnh hưởng cả cart, delivery).
- Redis dùng `allkeys-lru` và dùng chung với cart/delivery: khi thiếu bộ nhớ, key rate limit có thể bị
  đẩy ra làm reset bộ đếm.
- Triển khai thật có load balancer đứng trước nginx thì nginx cần `real_ip` (hoặc thêm LB vào
  trusted-proxies), nếu không mọi người lại chung IP của LB.
- PBL6-81 mô tả cùng lỗi này (phát hiện khi chạy test hiệu năng).

## 5. Sửa theo review PR #58

- **(Cao) nginx location tìm kiếm bằng ảnh không đặt `X-Forwarded-For`:** thêm `X-Real-IP`,
  `X-Forwarded-For $proxy_add_x_forwarded_for`, `X-Forwarded-Proto`, `X-Forwarded-Host` vào template
  trong `scripts/generate-search-contract.py` và block sinh ra trong `frontend/default.conf.template`.
  Script giờ kiểm tra mọi `location` có `proxy_pass` đều đặt XFF; thiếu thì `--check` (CI) báo lỗi.
- **Tra DNS tên host trusted proxy:** lần tra đầu chạy nền (không chặn khởi động gateway). Còn tên host
  chưa tra được (vd `frontend` khởi động sau gateway) thì thử lại sau 1s, 2s, 4s... tới chu kỳ refresh.
- **Khoá bucket chuẩn hoá cả IPv4:** `::ffff:a.b.c.d` và `a.b.c.d` ra cùng một khoá; `resolve()` trả địa
  chỉ kết nối ở dạng chuẩn.
- **Redis mất kết nối:** Lettuce `disconnectedBehavior=REJECT_COMMANDS` để lỗi ngay thay vì chờ timeout.
- **Theo dõi trạng thái dự phòng:** gauge `gateway.rate_limit.degraded` (1 = đang đếm trong RAM).
- **Test Redis thật:** `RedisRateLimiterRedisTest` (Testcontainers `redis:7-alpine`) chạy Lua script, kiểm
  tra đếm và TTL. Máy không có Docker thì tự bỏ qua; lúc sửa Docker không chạy nên test này **chưa chạy**.
- Không đổi: bean Redis khi `store=memory` (nit, không kết nối, giữ cấu hình đơn giản).
